Xray пути и порты

Где лежит Xray и на каких портах он слушает клиентов. Смена портов или адреса применяется только после перезапуска Xray.

Исполняемый файл Xray нужен для тестов прокси и применения конфига.
Куда панель пишет сгенерированный конфиг.
0.0.0.0: доступ с LAN, 127.0.0.1: только локально.
Клиенты подключаются к SOCKS/HTTP. API слушает только localhost и нужен панели для горячего применения узлов. Порты должны различаться; после сохранения нужен перезапуск Xray.

Отбор в конфиг лимиты и страны

Какие профили панель кладёт в конфиг Xray и в подписку: лимит, минимальная скорость, свежесть теста и страны. Почему конкретный профиль не попал — видно на странице «Источники» в блоке состава конфига.

Макс. активных прокси сколько самых быстрых попадает в конфиг и подписку
Мин. скорость Mbps 0 = без фильтра; ниже порога и незамеренные не попадают в конфиг
Свежесть профиля мин 0 = авто: два интервала проверки, от 3 часов до суток; старее не попадает в конфиг и подписку
Только замеренные в конфиг и подписку только профили с замером скорости; если замеров нет, конфиг пуст

Фильтр стран

Отмеченные страны исключаются из конфига и подписки. Отметки хранятся отдельно от поиска: найденное подмножество не теряет остальные страны.

URL проверки

Через этот адрес чекер проверяет туннель, а Observatory — узлы в работающем Xray. Живым считается любой HTTP-ответ.

URL проверки
если URL не отвечает, прогон сам переключится на рабочих кандидатов (Cloudflare, Google, Firefox…)
Автоподбор проверять URL перед прогоном и переключаться на лучший из каталога

Таймауты и повторы

Сколько ждать ответа и сколько раз пробовать. Больше терпения — больше найденных узлов, но дольше прогон.

Массовая проверка сек на одну пробу; 6-8 сек терпит медленные узлы
Повторы пробы раз доп. попытки с другим URL и большим таймаутом: защищённые серверы отвечают не сразу
Ручной тест одного сек щедрый таймаут для кнопки «Тест» у профиля
Применять конфиг пересобрать конфиг Xray после прогона

Производительность

Профили проверяются пачками в одном процессе Xray, пробы идут параллельно. Больше профилей за раз — быстрее прогон, но выше нагрузка на CPU и сеть.

Профилей за раз шт одновременных проверок = inbounds в одном процессе Xray; 128 — оптимум для VPS
Ожидание старта Xray ×0.05с пауза перед повтором, если Xray не ответил на порту
TCP-префильтр отсекать закрытый server:port до запуска Xray
Таймаут префильтра сек 2-3 сек: SYN к защищённым узлам идёт дольше
Повторы префильтра раз повтор с увеличенным таймаутом, если TCP не ответил сразу
Параллельных TCP шт независимо от пачки: префильтр проверяет тысячи адресов сокетами
Оценка прогона …

Тест скорости

Замер идёт по одному профилю, чтобы узлы не делили канал. Топ-N лучших по пингу; окно замера — фиксированное.

Включён
Через профили штатный замер по узлам; выключено — только прямой baseline панели (профили не обновляются)
Топ-N прокси сколько лучших по пингу замерять на скорость
Файл замера
10MB-файл; если основной недоступен, берутся запасные (Cloudflare → wcloud → Google 100MB/10MB → HuggingFace)
Длительность одного профиля сек фиксированное окно (рекомендуется 10)
Адаптивная проверка сек ранний выход только при заданном пороге «Мин. скорость»
Бюджет стадии сек 0 = без ограничения; 1200 хватает на 30 профилей по 10 с с запасом на таймауты, после бюджета остальные пропускаются
Прямой замер ещё не было

Расписание прогонов

Когда панель сама импортирует и проверяет профили. Ручной импорт тест не запускает.

Проверка из БД каждые …
15 мин1 ч3 ч5 ч
Авто-очистка удалять профили, упавшие трижды подряд
Импорт + проверка каждые …
1 ч8 ч16 ч24 ч

Импорт источников → проверка → скорость → конфиг. Ручной импорт тест не запускает.
